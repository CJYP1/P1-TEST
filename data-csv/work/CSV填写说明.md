# CSV 填写模板 — 使用说明

## 这是什么
9 个楼层 CSV 模板，格式已经全部正确。你只需往里填数字，推 GitHub 就能被读懂、不报错。

## 文件
B1 / B1M / B2 / L1 / L2 / L3 / L4 / L5 / OTHER —— 每个楼层一个文件。

## 列的含义（共13列，顺序不能改）
| 列 | 能不能填 | 说明 |
|----|---------|------|
| 大区 | 别动 | EB / NB / MA |
| 小区 | 别动 | 分区名，是定位键 |
| 工作项 | 别动 | 工作名称，是定位键 |
| 月份 | 别动 | 是定位键 |
| 序号 | 别动 | 同一小区同月的行顺序，改了会错位 |
| 计划量 | ✅填 | 计划要做多少 |
| 实际量 | ✅填 | 实际做了多少 |
| 完成率% | ✅填 | 0-100 的数字 |
| 单位 | 可填 | 如 m² / nos |
| 计划开始 | ✅填 | 格式必须 2026-04-01 |
| 计划结束 | ✅填 | 格式必须 2026-04-30 |
| 实际完成日期 | ✅填 | 格式必须 2026-04-15 |
| 标记 | 可填 | 备注 |

## 三条铁律（违反就构建失败）
1. **月份**必须是全称：`April 2026`（不能写 Apr-26）
2. **日期**必须是：`2026-04-01`（不能写 1/4/2026）
3. **序号**：同一小区+同月，从 0 开始连续（0、1、2…），别跳号别重复

## 怎么用
1. 打开对应楼层 CSV，往"计划量/实际量/完成率/日期"列填数
2. 保存（保持 UTF-8 编码）
3. 替换 GitHub 仓库 data-csv/work/ 里的同名文件
4. Commit + Push
5. 去 Actions 页看：绿勾=成功，红叉=有错（点进去看哪行）

## 出错了怎么办
Actions 红叉点进去，会告诉你"第几行 月份不合法/序号不连续"。照着那三条铁律改对，重推即可。
